# RAG X-Ray — Learn RAG by watching real data flow

An end-to-end, locally runnable **Angular + FastAPI + Sentence Transformers + ChromaDB + optional Ollama** application.

**Design:** simple document upload and chat workspace; click **Explore Document Journey** or **Explore Question Journey** to see real **Before → Operation → After → Next** intermediate values. There are no developer logs or trace IDs in the UI.

## Features

- Upload PDF, TXT or Markdown (10 MB max). See real extraction, cleaning, chunking, encoding, indexing stages as they finish.
- Actual `document_embeddings` generated by `sentence-transformers/all-MiniLM-L6-v2`, with shape and first vector values.
- Actual query embedding, stored vectors, cosine similarity and sorted candidates.
- Visual ranking with **Why?**, actual scores and vector previews. Model similarity is not a proof of which exact words caused a ranking.
- **Source to answer:** click a citation to inspect the original indexed passage.
- **What-if Top-K:** change selected chunk count, inspect new context preview, then re-run to generate an answer with that K.
- Large intermediate values are trimmed with **Show all values**; stages are navigable.
- Real answer via optional local Ollama; if unreachable, clearly-labeled **extractive fallback** with source snippets.
- Delete indexed documents. Prevent unready documents from answering.

## Requirements

- Python **3.11 or 3.12 recommended** (3.13 may work but some ML packages vary).
- Node.js **20.19+ or 22.12+**, npm.
- Free internet on first use to download Python packages, npm packages and the sentence-transformers model (unless already cached).
- Optional: [Ollama](https://ollama.com/), with `ollama pull llama3.2:3b` for generated answers.

## Run locally (Windows PowerShell)

**Terminal 1 — backend:**

```powershell
cd backend
py -3.12 -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -r requirements.txt
uvicorn app.main:app --reload --host 127.0.0.1 --port 8000
```

If only Python 3.11 is installed use `py -3.11 -m venv .venv`; on Linux/macOS use `python3 -m venv .venv` and `source .venv/bin/activate`.

**Terminal 2 — frontend:**

```powershell
cd frontend
npm install
npm start
```

Open **http://localhost:4200**. API docs at **http://localhost:8000/docs**. Upload `sample_docs/employee_handbook.txt` and explore **Document Journey**. Ask *How do employees request annual leave?*, open **Question Journey**, inspect rankings, citations and Top-K.

**Optional — actual LLM answers:**

```powershell
ollama pull llama3.2:3b
ollama serve
```

If Ollama already runs, do not start a second server. Default environment is `OLLAMA_URL=http://localhost:11434`, `OLLAMA_MODEL=llama3.2:3b`. With no Ollama model, the app uses real nearest-neighbor evidence, clearly labeled `extractive_fallback`.

### Docker backend option

```bash
docker compose up --build
```

Then run `npm install && npm start` in frontend on your host. The Docker backend accesses a host Ollama instance through `http://host.docker.internal:11434`; or run Ollama on the host and set env accordingly. The first Docker build and embedding model download require internet. The `./data` volume persists the index.

## How it works

### Document journey

`uploaded bytes → extracted pages → cleaned text → page-local word chunks (size 90, overlap 18) → normalized 384D document_embeddings → Chroma index`

### Question journey

`question → normalized query_embedding → cosine(query_embedding, stored vectors) → ranked_chunks → top_k context → Ollama or extractive response → source passages`

Each stage contains the **real input**, **operation**, **real output** and **next use**. For readability, the backend includes actual full vectors for up to **5 document chunks** and the full query vector in the inspector. Long JSON is clipped in the UI unless expanded. All vectors remain in ChromaDB and are used for scoring.

Cosine scores are **chunk-level**, not document-level. Ranking bars show scores between 0 and 1 when positive; negative scores still appear numerically. The **Why?** panel explains the computation, not a causal feature attribution.

## Testing

```bash
cd backend
python -m pytest -q
```

The unit tests exercise cleaning, chunk boundaries, similarity, vector preview and extraction without downloading an embedding model. For an integration smoke test, start the server, upload a text file, wait until its status is `ready` and use `/api/ask`.

## Important limitations

- **Local education/demo app**, not suitable for storing real employee/confidential material without authentication, tenant authorization, encryption and privacy controls. No account isolation is implemented.
- PDF scanned pages need OCR; this version supports text-based PDFs only.
- The document pipeline runs in a single local process executor; distributed job queue or multiple-instance orchestration is not implemented.
- Live progress uses HTTP polling every ~1.1 seconds, not fake timers. The progress bar is step-based, not an estimate of remaining wall time.
- Text splitting is intentionally simple **word-based**, not token-aware/semantic; inspect the real chunk text to see the effect.
- An uploaded document cannot be downloaded through the API; stored chunk/page previews are shown instead. Only chunks (not original raw files) persist after upload.
- Prompt-grounding and citation labels do not guarantee full answer faithfulness. Sources are inspectable for human verification.
- There is no authentication, vector re-ranking, batch retry, or production-grade ML monitoring.
